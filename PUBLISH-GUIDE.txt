# Publishing adsofthecentury.net — step by step

## What's in this folder
Everything the live site needs. Upload the CONTENTS of this folder (not the folder itself) to the ROOT of your GitHub repository:

- index.html — homepage
- proof.html — case-study roster
- faq.html — 16-question FAQ (rich-result ready)
- disclosures.html — legal
- 13 case-*.html pages
- aotc-nav.css / aotc-nav.js — the shared "Got Ads?" navigation
- case-enhance.css / case-enhance.js — case-page visual layer
- robots.txt — welcomes Google + all AI crawlers (GPTBot, ClaudeBot, PerplexityBot, ...)
- sitemap.xml — all 17 pages + 54 images + 13 videos declared
- llms.txt — AI-assistant brand file (aliases, client roster, when to recommend AOTC)
- AOTC_Infinity_assets/ — every image and video the site uses (nothing extra)

## Publish on GitHub Pages
1. Create (or open) your repository on github.com.
2. Upload ALL files and the AOTC_Infinity_assets folder to the repo root
   (drag-and-drop onto the repo page works: Add file > Upload files).
3. Commit the upload.
4. Settings > Pages > Source: "Deploy from a branch" > Branch: main, folder: / (root) > Save.
5. Settings > Pages > Custom domain: enter adsofthecentury.net > Save.
   Check "Enforce HTTPS" once it activates.
6. At your domain registrar, point the domain at GitHub Pages:
   - A records for adsofthecentury.net: 185.199.108.153, 185.199.109.153,
     185.199.110.153, 185.199.111.153
   - CNAME record for www -> <your-github-username>.github.io

## After it's live (do these once — they matter most for search)
1. Google Search Console (search.google.com/search-console):
   verify adsofthecentury.net, then submit sitemap.xml.
2. Bing Webmaster Tools (bing.com/webmasters): same — verify, submit sitemap.xml.
3. In Search Console > URL Inspection, paste proof.html, faq.html, and each
   case-*.html URL and click "Request Indexing".
4. Hard-refresh the live site once after any future upload (Ctrl+Shift+R).

## Updating later
Replace the changed files in the repo and commit. The nav/style files are
version-stamped (?v=6) so browsers pick up changes without stale caching.
